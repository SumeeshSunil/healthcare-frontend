1 Project Architecture & Core Systems Overview

The Healthcare Portal is a multi-tenant Single Page Application (SPA) designed to handle clinical operations across three primary user roles:

  • Patient: Search doctors, book consultation slots with dynamic weekday availability checks, view medical records (EHR), pay invoices, chat with doctors, and receive notifications.
  • Doctor: Configure weekly working days & time slots, review patient consultation queues, review past medical history, issue medical certificates, conduct live consultations with 1-0-1-0 dosage prescriptions, and chat with patients.
  • Admin: Review and approve/reject patient appointment requests, manage facility slot limits, view system-wide statistics, and oversee clinic operations.
Core Architectural Principle

All persistent global state is centralized inside the Redux Store (`redux/store.js`). Components read data using `useSelector` and mutate state via `useDispatch`. Shared UI feedback (toasts) uses the React Context API.

3 Every React Hook Used & How They Work

HookSourcePurpose in This Project
useState React Manages component-local state like search inputs, date picks, tab selections, modal visibility, and prescription form fields.
useEffect React Handles side effects: outside click detection in search dropdowns and auto-dismiss timers in Toast notifications.
useRef React Stores a mutable reference to DOM elements (e.g. search box) without causing re-renders when referenced.
useCallback React Memoizes functions (like addToast and removeToast) to keep function references stable across re-renders.
useContext React Allows components to call useToast() to trigger toast notifications from any page level.
useSelector react-redux Subscribes components to specific slices of Redux store state (e.g., appointments, doctors, messages, auth).
useDispatch react-redux Returns the dispatch function used to execute Redux actions.
useNavigate react-router-dom Programmatically redirects users between routes inside event handlers (e.g. after booking an appointment).
useParams react-router-dom Extracts dynamic URL route parameters (e.g., :doctorId in /patient/book-appointment/:doctorId).

5 Dynamic Doctor Schedule & Date Availability Filtering (doctorSlice)

How Dynamic Doctor Schedule Filtering Works

Previously, booking an appointment showed static time slots for any date. Now, Doctor Schedule configuration in `DoctorSchedule.jsx` is connected to `doctorSlice` in Redux and dynamically filters `BookAppointment.jsx`:

  • Doctor Configures Working Days: Doctor sets working days (e.g. Dr. Arjun is available Monday, Wednesday, Friday). Setting a day off-duty dispatches updateDoctorSchedule() to Redux.
  • Patient Picks Date: In BookAppointment.jsx, picking a date (e.g. 2026-07-28) calculates the weekday (e.g. Tuesday).
  • Off-Duty Guard: If doctor is off-duty on Tuesdays, the UI displays a clear notification: 🚫 Dr. Arjun Menon is Off-Duty on Tuesdays. Working days: Monday, Wednesday, Friday. and disables time slot selection.
  • Dynamic Time Slots: If doctor IS working on that day, it displays ONLY the specific time slots configured for that day.

6 Persistent Chat System Architecture (messageSlice)

Why messageSlice was created

Initially, messages were kept in component local state, meaning navigating through the sidebar or changing pages erased all messages. By moving message storage to Redux (`messageSlice.js`):

  • Cross-Role Synchronization: When a doctor sends a message in DoctorMessages.jsx, it is stored in Redux and immediately appears when logged in as that patient in Messages.jsx.
  • Navigation Persistence: Users can switch sidebar routes, navigate across pages, and return to chat without losing any sent or received messages.

7 Complete End-to-End Clinical Consultation Workflow (1-0-1-0 Dosage)

1

Patient Books Appointment with Date Availability Check

Patient selects a doctor, picks an active working date and time slot → Dispatches addAppointment() with status pending.

2

Admin Reviews & Approves Slot

Admin views slot occupancy in ManageSchedules.jsx → Clicks Approve → Dispatches approveAppointment() (status becomes confirmed) and addNotification() to alert patient.

3

Doctor Conducts Consultation & Prescribes (1-0-1-0 Timing)

Doctor sees confirmed appointment in DoctorAppointments.jsx → Clicks "🩺 Consult & Prescribe" → Opens consultation modal showing patient EHR history, chief complaint input, and dynamic medication prescription with 1-click 1-0-1-0 dosage timing buttons (Morning - Noon - Evening - Night).

4

Save & Complete (Multi-Slice Dispatch)

Doctor clicks "Save Prescription & Complete Consultation", triggering 4 automatic operations:

  • completeAppointment(id): Sets status to completed in appointmentSlice.
  • addRecord(newEhrRecord): Saves diagnosis, clinical notes, and medication list with 1-0-1-0 schedules into recordsSlice (viewable under Patient's MedicalHistory.jsx).
  • addBill(newInvoice): Creates unpaid invoice in billingSlice.
  • addNotification(alert): Notifies patient that consultation is complete and prescription is issued.
5

Patient Pays Invoice

Patient navigates to PatientBilling.jsx → Selects payment method → Dispatches payBill() → Bill status updates to paid.

10 Detailed Page-by-Page Logic Guide

Patient Pages

  • DoctorSearch.jsx: Search filter by name & specialization, auto-complete dropdown, click outside handler using useRef.
  • BookAppointment.jsx: Dynamically calculates date weekday, filters doctor availability, checks max 4-patient slot cap, dispatches addAppointment.
  • MyAppointments.jsx: Shows patient's booked appointments with status badges (pending, confirmed, completed, cancelled) and cancel action.
  • MedicalHistory.jsx: Displays patient's EHR records, diagnoses, physician notes, and prescribed medications with 1-0-1-0 dosage schedules.
  • PatientBilling.jsx: Invoice settlement screen. Select payment method to dispatch payBill.
  • Notifications.jsx: Real-time feed connected to notificationSlice with unread badges and click-to-read triggers.

Doctor Pages

  • DoctorDashboard.jsx: Summary metrics for doctor's daily consultations, pending requests, and completed visits.
  • DoctorAppointments.jsx: Doctor queue with status filter, EHR history preview, and interactive prescription modal with 1-0-1-0 schedule buttons.
  • DoctorSchedule.jsx: Weekly consultation hours configuration connected to Redux doctorSlice.
  • DoctorMessages.jsx: Doctor-side chat connected to Redux messageSlice.
  • IssueCertificate.jsx: Generator for medical leave / fitness certificates with printable preview.

Admin Pages

  • ManageSchedules.jsx: Admin verification panel for approving or rejecting pending patient appointment requests.
  • AdminAppointments.jsx: System-wide searchable table of all appointments across all doctors and statuses.
  • AdminDashboard.jsx: Clinic-wide analytics (total revenue, active doctors, total patients, appointment stats).

11 Complete Technical Interview Q&A Prep

Q1. How is state managed in this healthcare application?
State is divided cleanly between local state (`useState`) for transient UI inputs (like search text or tab selections), Context API for global Toast alerts, and Redux Toolkit (`configureStore`) for core domain entities like appointments, doctors, billing, notifications, EHR records, and persistent chat messages.
Q2. How does doctor availability dynamic filtering work when a patient books an appointment?
Doctors set their active working days in `DoctorSchedule.jsx` which dispatches `updateDoctorSchedule` to `doctorSlice` in Redux. When a patient picks a date in `BookAppointment.jsx`, the app calculates the weekday name (e.g. Tuesday). It checks `doctor.availability` from Redux. If off-duty, it displays an off-duty notice and disables booking. If available, it renders only the specific time slots configured for that weekday.
Q3. How does the complete appointment lifecycle work from booking to payment?
1. Patient books appointment → Dispatches `addAppointment` (status: `pending`).
2. Admin verifies slot capacity & approves → Dispatches `approveAppointment` (status: `confirmed`) & `addNotification`.
3. Doctor opens consultation workspace → Enters diagnosis & `1-0-1-0` medication prescription → Dispatches `completeAppointment` (status: `completed`), `addRecord` (EHR), `addBill` (invoice), & `addNotification`.
4. Patient views invoice in `PatientBilling.jsx` → Dispatches `payBill` (status: `paid`).
Q4. Why was a Redux `messageSlice` created instead of using local component state for messaging?
Local state is unmounted when a user navigates away or switches sidebar links, which erased chat history. Creating `messageSlice` in Redux persists conversation logs globally. When a doctor sends a message, it is stored in Redux and immediately available when switching to the patient view or navigating across pages.
Q5. How does ProtectedRoute restrict unauthorized access?
`ProtectedRoute` is a higher-order guard component wrapping protected routes in `AppRoutes.jsx`. It reads the Redux auth state. If the user is unauthenticated, it renders ``. If `allowedRoles` is passed and the logged-in user's role is not included, it renders ``.
Q6. What is the purpose of `useRef` in `DoctorSearch.jsx`?
`useRef` is used to attach a direct reference to the search container DOM element. Inside a `useEffect` event listener for `mousedown`, we check if `searchRef.current.contains(event.target)`. If the click occurred outside the container, `setShowSuggestions(false)` is called. `useRef` holds this DOM reference without causing extra re-renders when updated.
Q7. How does Redux Toolkit simplify Redux development compared to classic Redux?
Redux Toolkit's `createSlice` automatically generates action creators and action types from reducer function names, eliminating string constants. It also integrates Immer internally, allowing developers to write direct state mutation syntax (like `state.push()`) safely while producing immutable state updates behind the scenes.
Q8. How does the Toast notification system work using Context API?
In `Toast.jsx`, a `ToastContext` is created with `createContext(null)`. `ToastProvider` wraps the entire app in `main.jsx` and maintains the list of active toast popups. The `useToast()` custom hook calls `useContext(ToastContext)`, giving any component instant access to helper methods like `toast.success()`, `toast.error()`, and `toast.warning()`.
Q9. What is the difference between `useNavigate` and `` in React Router v6?
`useNavigate` is a React hook that returns a function for programmatic navigation inside event handlers or side effects (e.g. `navigate('/patient/my-appointments')` after form submission). `` is a React JSX component used in conditional rendering (e.g., returning `` inside `ProtectedRoute` when not authenticated).
Q10. How is the 1-0-1-0 prescription schedule stored and displayed?
During consultation in `DoctorAppointments.jsx`, the doctor selects dosage schedule presets like `1-0-1-0` (Morning - Noon - Evening - Night). On save, this is dispatched inside an array of prescription objects to `recordsSlice`. `MedicalHistory.jsx` reads this slice using `useSelector` and displays the medication name, dosage timing (`1-0-1-0`), and duration under the patient's EHR records.
Q11. How does `useCallback` optimize performance in `Toast.jsx`?
`useCallback` memoizes the `addToast` and `removeToast` functions so their reference memory addresses remain identical across re-renders. Because these functions are passed to child components, memoizing them prevents child components from re-rendering unnecessarily.
